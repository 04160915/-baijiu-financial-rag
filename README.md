# 白酒行业财报问答知识库（RAG）

13 家中国白酒上市公司 **2026 年半年度报告**的检索增强问答系统。
自己下载原文 → 抽取文本和表格 → 切块 → 建「向量 + BM25」双索引 → 出一个带**出处**的问答页面。

| 项 | 数量 |

## 三、怎么跑

> 已经跑完的中间产物（`chunks.jsonl`、`bm25_corpus.json`、`vectors.npy`）都在仓库里，
> **只想看页面的话，直接双击 `打开提问页面.bat` 就行**，不用重跑。

要完整重跑一遍（按顺序）：

| 顺序 | 命令 | 耗时 |
|---|---|---|
| ① | `python 下载器_半年报.py` | 几分钟 |
| ② | `python 提取器.py` | 几分钟 |
| ③ | `python 切块.py` | 几秒 |
| ④ | `python 向量化.py` | **CPU 上约 100 分钟**（可断点续传） |
| ⑤ | `python 建BM25.py` | 几秒 |
| ⑥ | 双击 `打开提问页面.bat` | — |
| ⑦ | `python 测试题.py --mode bm25`（或 `hybrid`） | 十几秒 |

第 ④ 步是唯一慢的。它是**纯本地计算**，不联网、不调 API。

依赖：`torch` `transformers` `rank_bm25` `jieba` `numpy` `streamlit`
（另外 `openai` 是可选的，装了就支持"让模型基于原文写答案"那一步）

## 四、几个关键设计决定

**1. 分词器只有一份（`分词.py`）**
索引端和查询端必须用**同一套词典**。分开写两份的话，索引里存的是 `复合计征`、查询却切成 `复合`+`计征`，**永远匹配不上，而且不会报错**——只会静默地少召回。
这个坑真踩过：一开始两边各写一份，Recall@5 只有 55%，合并成一份之后到 77%。

**2. 向量算完之前，主动禁用向量检索（`检索.py`）**
`向量化.py` 是每若干批落一次盘的，中途 `vectors.npy` 已存在但没算完的行是**全零**。零向量的余弦相似度是 0，会静默排到最后。
所以 `检索.py` 开机会检查有没有零行，有就打印警告并**禁用向量路**，而不是拿半个索引当真。这是同一个"静默错结果"教训的第二次应用。

**3. 长度归一化的副作用**
BM25 对短块天然有利。页脚那种极短的块偶尔会窜到第 1 名。实测这一类块的 BM25 得分挤得非常近（0.0154~0.0164），名次其实很脆弱。

**4. 用 RRF 融合两路**
RRF（Reciprocal Rank Fusion，k=60）只看**名次**不看分数，所以不需要把 BM25 分数和余弦相似度归一化到同一量纲——那件事没有干净的做法。

**5. 判对错交给程序，不靠嘴说**
`验收BM25.py` 和 `测试题.py` 都要求预先写死"标准答案块"的判定条件，然后自动在 5861 块里找它、看它进没进前 K 名。
**不这么做的话，"效果不错"就全凭我说，等于没测。**

## 五、实测效果

判分方式：不看模型写了什么，只看**含答案的那个块**进没进前 5 名。

### 第⑤步验收（15 题，`验收BM25.py`）

| 指标 | raw（不过滤公司） | flt（认公司名后只搜该公司） |
|---|---|---|
| Recall@5 | 73% | **80%** |
| MRR | 0.650 | **0.710** |

分类别看（flt）：单公司精确数字 100%、政策条款 100%、公司名干扰 100%、跨公司全景 67%、口语化 0%。

### 第⑦步 10 道测试题（`测试题.py`）

见 `记录/第七步测试题记录_*.txt`。

**BM25 单路的基线是 Recall@5 = 67%（6/9），MRR 0.420。**
分界线很干净：单公司数字题 3/3、政策条款题 3/3 全中，**跨公司全景题 0/3 全灭**。

## 六、已知局限（这些是要写进结论的）

**1. 跨公司全景题，检索救不了。**
「哪家公司消费税占营业收入比重最高」这种题，答案**根本不存在于任何一个块里**——要把 13 家各自的数取出来再相除比较。
检索再准也变不出来，必须"多轮取数 + 自己算"。
这不是检索质量问题，是架构问题。

**2. 有一类问题会"自信地答错"。**
问「白酒企业的税负重不重」，全库 168 处「税负」**全部是「递延所得税负债」的连读**，没有一处是"税负重"的意思。
检索会返回一堆 `所得税费用包括当期所得税和递延所得税` 之类**完全无关**的内容——比"找不到"更危险。

**3. `口子窖` 的税金及附加表跨页了。**
表头在第 147 页、数字在第 148 页，切块切在了中间。按页切块必然有这类问题。

**4. 块粒度偏粗。**
有的块"包含答案"，但块的开头在说完全不相干的事（比如开头讲"售后租回"，税率表埋在中间）。按"块里有没有答案"判它算命中，可人翻开一看会觉得文不对题。

**5. 第 ④ 步在纯 CPU 上要 100 分钟。**
用 GPU 会快一两个数量级，但本机没有可用的 CUDA 环境。
